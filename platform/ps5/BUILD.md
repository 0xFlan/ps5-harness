# PS5 agent build and package

Status: **the real agent cross-builds, links, validates and runs on a console.**
`make -C platform/ps5` produces `eboot.bin` and `harness.elf` from the same
`src/*.cpp` sources as the host harness, linked against PacBrew's static
libcurl/OpenSSL, plus a real SFO and icon. Boot, resources, TLS, `dlopen` and
writes were observed on a PS5 on 2026-11-18; the evidence is in
`docs/CONSOLE-REPORT.md`. The title-install path is still untested.

The package contains:

- `eboot.bin` — a fake SELF (`4f15 3d1d`) packed by the SDK's `make_fself.py`
  from a separate non-PIE link, for a loader that installs a title.
- `harness.elf` — the real x86-64 FreeBSD **PIE/ET_DYN** agent, for a loader
  that takes raw ELF (elfldr on port 9021). It is the agent, not the bring-up
  probe.
- `sce_sys/param.sfo` — a real SFO binary generated by
  `platform/ps5/tools/make_sfo.py`.
- `sce_sys/icon0.png` — a real 512x512 RGBA PNG generated by
  `platform/ps5/tools/make_icon.py`. It uses the shell's visual language: a
  near-black cool gradient, soft vignette, a white H monogram and one restrained
  blue bridge. The title is intentionally not baked into the tile; the shell
  renders it from `param.sfo`/`param.json`.
- `sce_sys/param.json` — JSON metadata some installers stage instead of an SFO.

`make -C platform/ps5 bringup` still builds the P2 resource-probe ELF (without
libcurl) for diagnostics. It is not part of the package and is not the artifact
the checklist asks you to install.

```
prospero-clang++ ... -DPS5H_PS5_TARGET -DCURL_STATICLIB \
  -Wl,--no-pie -Wl,--wrap=fcntl \
  src/*.cpp console_compat.cpp \
  -lcurl -lpsl -lssl -lcrypto -lzstd -lz -ldl -pthread
```

The elfldr link is identical without `-Wl,--no-pie`, so `harness.elf` is ET_DYN.

### Two ELF forms

elfldr maps ET_DYN payloads; an ET_EXEC `harness.elf` fails at spawn with
`[elfldr.elf] Error spawning payload` on hardware. `make_fself.py` is the
opposite: it accepts ET_EXEC (and SCE variants), not ET_DYN. The build therefore
links the same sources twice: `harness.elf` stays PIE for elfldr, and
`harness-nopie.elf` is the fixed-address input for `eboot.bin`.
`ps5_package_test` asserts that the packaged `harness.elf` is ET_DYN.

`-Wl,--wrap=fcntl` routes curl's socket-flag calls through `console_compat.cpp`
in both links.

## Console glue

`platform/ps5/console_compat.cpp` is compiled only into the target:

- **CA bundle** — `ps5h_console_ca_bundle()` prefers `PS5H_CA_BUNDLE`, then
  `/<sandbox word>/common/cert/CA_LIST.cer` (using
  `sceKernelGetFsSandboxRandomWord()`), then
  `/system/common/cert/CA_LIST.cer` for an elevated title. The console's
  `CA_LIST.cer` is a PEM file OpenSSL can read directly; verification is never
  disabled.
- **Non-blocking sockets** — `ps5h_console_nonblocking()` sets the console's
  `SO_NBIO` (`0x1200`), which `CURLOPT_SOCKOPTFUNCTION` applies to every socket.
  curl's own `fcntl(O_NONBLOCK)` does not do this on the console.
- **`fcntl` wrapper** — `__wrap_fcntl` accepts `FD_CLOEXEC` when the sandboxed
  libc returns `EINVAL`, and maps `O_NONBLOCK` to `SO_NBIO`. Files and pipes
  stay on the real call; `ENOTSOCK` is treated as a harmless file flag.

The SDK's payload libc already exports `getaddrinfo`, `freeaddrinfo`,
`gethostbyname`, `getnameinfo`, `fnmatch`, `gmtime_r`, `getpwuid_r`, `pipe2`,
`openlog`, `closelog`, `dladdr` and `if_nametoindex`, so the libc stand-ins that
native titles need were not required for this link. The link proves symbol
resolution; DNS/TLS behaviour was then verified on the console (see above).

## Runtime scaling

`src/resources.cpp` probes the process, `src/runtime.cpp` turns the probe into
a budget, and `src/pool.cpp` executes one turn's tool calls across it:

- **Workers** — `workers = cpu_online`, reduced only when the fd limit cannot
  support 8 descriptors per worker plus 24 for the process. `raise_fd_limit()`
  first raises `RLIMIT_NOFILE` soft to the loader's hard limit.
- **Buffered responses** — `max(1 MiB, visible_memory / 16)`, using available
  memory when the platform reports it, total memory otherwise, and further
  capped by `RLIMIT_AS` and `RLIMIT_DATA` when finite. The old fixed 4 MiB
  ceiling is gone; the cap is a share of measured memory.
- **File reads** — `min(buffered, 4 MiB)`: the model context, not console
  memory, is the binding constraint on text sent to the provider.
- **Downloads** — capacity is the destination filesystem's free space minus a
  1% reserve capped at 64 MiB, and also bounded by `RLIMIT_FSIZE` when set.
  The streaming client stops when written bytes would exceed it.
- **Deadlines** — each tool call keeps its own deadline; a hung handler is
  abandoned, not joined.

`harness --resources` prints the probe and budget on the host;
`tests/resources_test.cpp`, `tests/runtime_test.cpp` and the parallel tool-call
case in `tests/e2e_agent_test.cpp` assert the scaling rules.

## On a console

Record the environment first: host OS and LLVM version, SDK zip sha256, PacBrew
version and bundle sha256, console firmware/exploit version, and the artifact
build id.

### Load the ELF

With `ps5-payload-elfldr` listening on 9021, upload `harness.elf` to the
console and send a `file:` URI. Arguments follow `?args=`; percent-encode the
spaces between them and backslash-escape any space inside an argument, because
the loader splits on unescaped spaces:

```bash
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--resources\n' \
  | nc -w 60 <console-ip> 9021
```

The agent appends diagnostics to `/data/ps5-harness-agent.log`, then
`/user/homebrew/ps5-harness-agent.log`, then `./ps5-harness-agent.log`
(`--log <path>` overrides). The first lines contain `build=… title=PHAR00001`,
the resource probe, and the runtime budget. A launch with no args prints usage
and exits 2; the packaged title path still supplies no arguments.

To run a turn, pass `--config` and `--prompt` through the `file:` URI, and
provide the model key in the environment named by the config. The key is never
read from the config file; a title launch cannot supply either the arguments or
the environment.

### Rest mode

`harness.elf` is a payload, not a background service. `platform/ps5/Makefile`
labels it "Loadable by elfldr on port 9021: ET_DYN, arguments supplied by a
file: URI"; this section's launch sequence is the only runnable path. The
process entry is `src/main.cpp`; every command path returns except the explicit
`--serve` browser mode, which blocks while its LAN listener is open. That mode
still starts only after a human launches `harness.elf` with `--serve`; it is not
started by the title path or by rest mode. `src/http.cpp` remains an outbound
libcurl client. Ports 9021 and 8888 are the external elfldr and file-manager
processes recorded in `docs/CONSOLE-REPORT.md:13`.

Rest mode stops that userland, so the harness, elfldr and the file manager are
not there to serve. The only path to work happening while the console sleeps is
to queue it on an always-on host and run it after the console wakes and
`harness.elf` is launched again. There is no wake-on-LAN, scheduler or
background-service path in this build.

### Local agents

Agent profiles are plain JSON files in `/data/homebrew` by default, or in the
directory passed to `--agents`. They are read on every launch, so editing one
on the console changes the next run without a rebuild. A profile can set a
description, `system_prompt` or `system_prompt_file`, model, temperature,
`max_tokens` and `max_steps`; it cannot change roots, URL policy, secrets,
endpoint/plugin directories or `delegation_max_depth`.

A run exposing the `delegate` tool can hand a subtask to another profile. The
child inherits the parent's tools and guards, so its filesystem, URL, secret and
endpoint access cannot exceed the main config. `delegation_max_depth` (default
2, `--max-depth` override) bounds nesting, and child steps/tokens come out of
the parent's budget. Successful and refused calls are logged with the profile,
depth and accounting. The host e2e suite exercises a full parent/child provider
round trip; the console check below only proves the tool and profile paths are
installed, because no model key is staged there.

```bash
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--list-agents\n' \
  | nc -w 30 <console-ip> 9021
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--agent%%20archivist%%20--agent-info\n' \
  | nc -w 30 <console-ip> 9021
```

`--agent-info` resolves the prompt and model without calling a provider, so it
is the console check that works before an API key is staged. To run a turn, pass
`--agent <name>` and `--prompt` through the same `file:` URI.

### Skills and file edits

Skills are directories under `/data/homebrew/skills/<name>/` on the console
(`skills` on the host), each with a `SKILL.md`. `skills_dir` in the main config
or `--skills <dir>` selects another root; a profile cannot set it. Stage a pack
with the normal upload path, then list or load it without a rebuild:

```bash
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--skills%%20/data/homebrew/skills%%20--call%%20skill%%20--args%%20%%7B%%7D\n' \
  | nc -w 30 <console-ip> 9021
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--skills%%20/data/homebrew/skills%%20--call%%20skill%%20--args%%20%%7B%%22name%%22%%3A%%22console-notes%%22%%7D\n' \
  | nc -w 30 <console-ip> 9021
```

`fs_write` creates or replaces a file under the write roots. `fs_edit` replaces
exact text and refuses a missing or ambiguous match unless `replace_all` is
true; it caps the file at 8 MiB and renames a sibling temporary file into place.
Both are compiled into every run, including delegated children. The default
prompt tells the model to read before editing and to report the path from the
tool result.

### Recon, plan, swarms and missions

The four recon tools are read-only and use the same `read_roots` and secret
rules as `fs_read`. `env_info` reports the build, platform, budget and system
mounts; it filters `/mnt/sandbox/...` entries belonging to other titles and
caps the list. `fs_tree` is depth/entry bounded and never follows a symlink.
`file_info` identifies ELF/Mach-O/PE headers and hashes files up to 64 MiB;
`fs_strings` reads at most 16 MiB and returns at most 200 strings.

```bash
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--call%%20env_info%%20--args%%20%%7B%%7D\n' \
  | nc -w 30 <console-ip> 9021
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--call%%20file_info%%20--args%%20%%7B%%22path%%22%%3A%%22%%2Fdata%%2Fharness.elf%%22%%7D\n' \
  | nc -w 30 <console-ip> 9021
```

`--plan` removes every mutating tool before the model or a child runs; it is a
registry guarantee, not a prompt request. `swarm` runs at most eight children
with the shared delegation budget, and `--mission` runs a bounded JSON sequence
of steps or swarms. The example mission can be staged beside the harness:

```bash
# upload examples/missions/local-map.json to /data/local-map.json first
printf 'file:/data/harness.elf?args=--config%%20/data/ps5-harness.json%%20--agents%%20/data/homebrew%%20--mission%%20/data/local-map.json\n' \
  | nc -w 900 <console-ip> 9021
```

A mission with no provider key still parses and runs its step; the first
provider call fails, the runner returns `ok:false` at that step, and later
steps do not run. Use that to verify the launch path without spending tokens.

## What this does not prove

- That the fake SELF is accepted by the loader or that the title launches.
- That the SFO key set and `--paid`/`--ptype` values suit your firmware.
- That a title launch can receive the `--config`/`--prompt`/key it needs.
- That `dlopen` loads a plugin `.so` inside a title sandbox (it works from the
  elfldr payload path).
- That a delegated model turn runs on hardware. The tool and failure path are
  console-verified, but no provider key was staged for a child run.
- That USB writes work; no USB device was present.
- That the browser workspace works from the console runtime: `--serve`,
  token authentication, the LAN listener, session persistence and a model turn
  through the UI are host-tested and cross-built but have not been run on the
  PS5. The new power tools and `sysctl` have not been run on hardware either.
- That the exact `CA_LIST.cer` path and resolver used are the intended ones;
  TLS succeeded and a bad certificate failed, but the path is not logged.

Those are console checks in `docs/HARDWARE-CHECKLIST.md`. TLS, `dlopen` and
writes are now claimed for the elfldr payload path, not for a title sandbox.
