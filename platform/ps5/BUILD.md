# PS5 cross-build and package (P2)

Status: **the package builds and is host-validated on this Mac; nothing has run
on a console.** P2 is incomplete until the payload boots on a PS5 and writes its
log line. The host checks below prove file structure, not console behaviour.

## What the build produces

| `bringup.elf` | 111,664 | `763823d2935afd95df9784298e7380daf939e9122b1c998166f02b7bf4102172` |
| `sce_sys/param.sfo` | 376 | `6bf5d47549c9314c6cf5b5355cae17f1603c210ff6aaafa52978221c6e19803f` |
| `sce_sys/icon0.png` | 4,223 | `38c53aee2109dc4b3200b98dcacf8a294388b84436c97298933abb0947ebbef8` |

Measured from build id `0.1.0-56c6056`. The build id embeds `VERSION` and the
commit, so any commit or source change alters these hashes; quote the build id,
not only a hash, in a console report.

The package contains:

- `eboot.bin` — fake SELF (`4f15 3d1d`) packed from the ELF by the SDK's
  `make_fself.py`, for a loader that installs a title.
- `bringup.elf` — the real x86-64 FreeBSD ELF, for a loader that takes raw ELF
  (elfldr on port 9021).
- `sce_sys/param.sfo` — a real SFO binary, generated by
  `platform/ps5/tools/make_sfo.py`; not JSON and not a renamed text file.
- `sce_sys/icon0.png` — a real 512x512 RGBA PNG, generated by
  `platform/ps5/tools/make_icon.py` (standard library only: no Pillow, no
  ImageMagick).
- `sce_sys/param.json` — the JSON metadata some installers stage instead of an
  SFO. It mirrors `title.mk` and is not read by the harness.

The title identity has one source, `platform/ps5/title.mk`:

```
TITLE_ID   := PHAR00001
TITLE      := PS5 Harness
CONTENT_ID := UP9000-PHAR00001_00-PS5HARNESS000001
APP_VER    := 01.00
```

`PHAR00001` is a homebrew-range ID (four uppercase letters, five digits), not a
Sony title ID, and does not sit in the `PPSA`/`CUSA` retail ranges. Change it in
`title.mk`; the SFO, `param.json`, package folder and payload log all follow.

## The SFO

`param.sfo` is little-endian: a 20-byte header (`\0PSF` magic `0x46535000`,
format version `0x00000101`, key-table offset, data-table offset, entry count),
one 16-byte entry per key (key offset, format, length, max length, data offset),
then a NUL-separated key table and a 4-byte-aligned data table. Strings are UTF-8
with a trailing NUL counted in both lengths; integers are one u32. The generated
file has 10 entries:

| Key | Format | Value |
|---|---|---|
| `APP_TYPE` | int | `1` |
| `APP_VER` | UTF-8 | `01.00` |
| `ATTRIBUTE` | int | `0` |
| `CATEGORY` | UTF-8 | `gd` |
| `CONTENT_ID` | UTF-8 | `UP9000-PHAR00001_00-PS5HARNESS000001` |
| `PARENTAL_LEVEL` | int | `1` |
| `SYSTEM_VER` | int | `0` |
| `TITLE` | UTF-8 | `PS5 Harness` |
| `TITLE_ID` | UTF-8 | `PHAR00001` |
| `VERSION` | UTF-8 | `01.00` |

The payload SDK has no SFO writer (its `install_app` sample stages `param.json`
and lets the system build the SFO), which is why the generator lives in this
repo.

## Build

```bash
mkdir -p .deps && cd .deps
curl -fsSLO https://github.com/ps5-payload-dev/sdk/releases/latest/download/ps5-payload-sdk.zip
unzip -q ps5-payload-sdk.zip
cd ..
export PS5_PAYLOAD_SDK="$PWD/.deps/ps5-payload-sdk"
export LLVM_CONFIG=/opt/homebrew/opt/llvm/bin/llvm-config   # any llvm-config 15–23
make -C platform/ps5
```

Verified on macOS 26.6.2 (arm64) with payload SDK v0.45 (zip sha256
`5fac6409…`) and LLVM 23.1.4. `make_fself.py` accepts `ET_EXEC`, not `ET_DYN`;
the SDK driver defaults to PIE, so the Makefile passes `-Wl,--no-pie`. Without
it the pack step fails with `ElfError: 'Unsupported type.'`.

Without the payload SDK (host-only checkout, CI) the generated assets still
build:

```bash
make -C platform/ps5 host-assets    # only sce_sys/param.sfo and icon0.png
```

## Host validation

`make test` regenerates the SFO and icon, then runs `build/ps5_package_test`
against `.deps/ps5-build/PHAR00001`:

```bash
make -C platform/ps5 host-assets
./build/ps5_package_test .deps/ps5-build/PHAR00001
```

The check parses `param.sfo` back from disk and asserts the magic, format
version, entry-table bounds, unique keys, 4-byte data alignment, NUL-terminated
UTF-8 values, the required keys (`APP_TYPE`, `APP_VER`, `CATEGORY`,
`CONTENT_ID`, `TITLE`, `TITLE_ID`, `VERSION`), `TITLE_ID` equal to the package
folder and in 4-letters/5-digits form, `CONTENT_ID` in Sony's 36-character form,
`CATEGORY` `gd`, `APP_VER`/`VERSION` `NN.NN` and equal, and `APP_TYPE` 1–3. It
walks every PNG chunk, verifies CRCs, the zlib header, the chunk order and
512x512x8-bit RGBA geometry, and — when the payload SDK build is present — the
fSELF magic and the ELF class/type/machine.

Where no `eboot.bin` exists (CI), it runs in `--assets-only` mode and requires
the SFO and icon only. Full mode requires all four files. Negative checks on
2026-11-18: a missing icon, an SFO with corrupted magic, a truncated PNG and a
missing `eboot.bin` each produced a `FAIL` line and exit status 1.

## On a console

Record the environment first: host OS and LLVM version, SDK zip sha256, console
firmware and exploit version, and the artifact build id. Without those a failure
cannot be reproduced.

### Load the ELF (fastest P2 check)

With `ps5-payload-elfldr` listening on 9021:

```bash
nc -w 30 <console-ip> 9021 < .deps/ps5-build/PHAR00001/bringup.elf
```

Then read the log the payload wrote, in the order it tried:
`/data/ps5-harness-bringup.log`, `/user/homebrew/ps5-harness-bringup.log`,
`./ps5-harness-bringup.log`, `/mnt/usb0/…`, `/mnt/usb1/…`. The first line
contains the build id and `title=PHAR00001`; a fault appends one
`CRASH build=… title=… signal=N (NAME) addr=0x…` line and exits `128+N`.

### Install as a title (untested sequence)

This mirrors the SDK's `install_app` staging over FTP (port 2121) and has **not
been run** on any firmware. It is the concrete starting point, not a recipe
known to work.

```bash
export PS5_HOST=<console-ip>
curl -Q "MTRW" ftp://$PS5_HOST:2121
curl -Q "MKD /system_ex/app/PHAR00001"         ftp://$PS5_HOST:2121 || true
curl -Q "MKD /system_ex/app/PHAR00001/sce_sys" ftp://$PS5_HOST:2121 || true
curl -Q "MKD /user/app/PHAR00001"              ftp://$PS5_HOST:2121 || true
curl -Q "MKD /user/app/PHAR00001/sce_sys"      ftp://$PS5_HOST:2121 || true

curl -T .deps/ps5-build/PHAR00001/eboot.bin       ftp://$PS5_HOST:2121/system_ex/app/PHAR00001/
curl -T .deps/ps5-build/PHAR00001/sce_sys/param.sfo  ftp://$PS5_HOST:2121/user/app/PHAR00001/sce_sys/
curl -T .deps/ps5-build/PHAR00001/sce_sys/icon0.png ftp://$PS5_HOST:2121/user/app/PHAR00001/sce_sys/
```

If that firmware's installer expects `param.json` rather than `param.sfo`,
upload the package's `sce_sys/param.json` in its place. Then refresh the shell
and launch **PS5 Harness**. Record what appears (title, icon, error text) in
`docs/HARDWARE-CHECKLIST.md`.

### Pre-flight

- [ ] Console on a firmware with a working payload loader; recovery path known.
- [ ] USB stick formatted and empty (the payload writes a log there if it can).
- [ ] Console clock correct if TLS will be tested later.
- [ ] `PHAR00001` unique on this console, or changed in `title.mk` and rebuilt.

## What this does not prove

That the fake SELF is accepted by the loader on your firmware, that `--paid` is
right for your setup, that the mounts exist and are writable, that the SFO keys
are the set your installer wants, that the icon is accepted, or that a title
launches. Those are console checks in `docs/HARDWARE-CHECKLIST.md`.

## Known risks at this stage

| Risk | Symptom | First check |
|---|---|---|
| Fake SELF rejected by the loader | Title does not appear, or system error on launch | `--paid`/`--ptype` values, loader docs for your firmware |
| SFO key set differs on this firmware | Install fails, no icon, or no entry in the shell | Compare with a working homebrew title's `param.sfo` |
| Sandbox write denial | No log file, but the title ran | Own folder vs `/data/homebrew` vs USB |
| CA bundle missing (P3) | TLS fails with a verification error, not a timeout | Bundle present and path logged |
| Console clock wrong (P3) | Cert "not yet valid" / "expired" | Time before certificates |
| `dlopen` unavailable (P3) | Plugin load fails, manifest tools fine | `dlerror()` text |
| No exceptions/RTTI (full harness) | Link errors around `std::function` | Compile the deadline path for the target first |
